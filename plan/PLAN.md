# Website plan

This repository already contains the GitHub template files. To build this website, tell the coding
agent **`Implement plan/PLAN.md`**. The agent should read the
[build instructions](PROMPT_TEMPLATE.md) in this folder and the root [AGENTS.md](../AGENTS.md), then
implement the brief below.

Replace the bracketed prompts before handing this plan to the agent. Remove optional entries that
do not apply. Record business-specific requirements here so the shared prompt can be reused as-is.

## Business and audience

- Business and website purpose — [Name, what it offers, who it serves, and whether this is a real website or a sample for the Jamstacks gallery.]
- Visitor priority — [The first question the home page should answer and the main action visitors should take.]
- Business details — [Public contact info, and if relevant, location or service area, opening hours and IANA time zone.]
- Public metadata — [Short description, domain if known, and relevant schema.org type. For a gallery template, give its template ID and gallery name.]

## Pages and content

- Home — [Lead message, primary action and sections in order.]
- Other pages — [Route, purpose and sections for each page, plus navigation labels. Include Contact and a customized 404.]
- Core content — [Collections such as services, menu or projects, their fields and entries, and the owner's most frequent edits.]
- Contact — [Enquiry purpose, public email, and what visitors should include in a message.]

## Design and behavior

- Visual direction — [Mood and concept, layout, typography, palette in both themes, textures and a distinctive element tied to the business.]
- Artwork — [The bespoke illustrations to draw (hero scene, section motifs, dividers, icons, 404 and OG art) and the style they share.]
- Page compositions — [For each page, how every section looks: its layout, the art it uses and how its content is presented. Sections should vary from one to the next.]
- Interactions — [Any filters, map, opening-hours display or other behavior, including how it should work without JavaScript.]
- Acceptance criteria — [Visual criteria that can be checked in screenshots, plus brief-specific scenarios and content rules, in addition to the shared checks.]
